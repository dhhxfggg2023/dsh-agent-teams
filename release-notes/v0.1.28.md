# v0.1.28 — interrupted hand-offs recover, and mail is never lost or unbounded

Release on npm `latest`; recommended host: Harness `0.2.1-rc.3`. No host-facing API changed: this release only fixes states a healthy run never reaches.

## Fixes

- **An interrupted reassignment no longer strands a member and its task.** `reassign_task` stops the current member and re-queues the task under the team lock, and a crash between those two writes left `member.stopping` and `task.reassigning` set forever: the member could not claim again and the task could not be claimed by anyone, with no tool able to release either flag. Both locks now come from one source of truth, `releaseHandoffFences` in `src/state.ts`: halting a team releases every in-flight hand-off (every hand-off is over once the team is halted), while resuming releases only a pair whose owning member no longer exists or was removed — a member that is still draining keeps its fence, so a resume cannot hand work to a member that is still finishing.
- **Mail is no longer deleted when its team disappears mid-step.** Mailbox admission swaps the receipt-bearing input for the current messages it resolved. When `readTeam` returned nothing — the team was archived between dispatch and the step — the batch resolved empty and the whole input was dropped, so a turn whose only input carried the message body became an empty step. The unresolved batch is now passed through untouched and only its acknowledgement is skipped.
- **Settled mailbox records are compacted.** The inbox is an append-only JSONL file that was rewritten on every append and acknowledgement and never shrank: a long-lived member carried every message it had ever read. Compaction now happens inside the write that acknowledges the messages, keeping every unread, discarded and unparseable row plus the newest 64 settled rows, and it preserves row order — a compaction that reorders history breaks readers that treat the file as a log.
- **The staged-plan editor no longer loses work.** Collapsing the Members or Tasks section unmounted its editors and destroyed typed text and the pending-edit flag; both sections now stay mounted and are hidden, and a polled remote update cannot overwrite an edit in progress (`if (dirty || busy) return` guards both sync effects). **Approve & Run** takes a two-step confirmation on the same button, and `busy` is cleared in a `finally`, so a rejected or failed request cannot leave the panel permanently disabled.

## Verification

- `pnpm build`, `pnpm typecheck`, `pnpm verify` and the harness-contract chain (lifecycle 120 checks, stress 18, modern- and delivery-harness runs) on the `0.2.1-rc.3` cohort.
- New suite `scripts/handoff-and-mailbox.test.mjs` (`pnpm verify:durability`, wired into `pnpm verify`) covers the four recovery paths directly: halt releases an interrupted fence, resume keeps a live fence and releases a removed owner's, an archived team passes a receipt input through with its body intact, and 100 settled records plus one unread compact to a bounded file that keeps the unread record.
- Environment limit, unchanged from 0.1.27: the two symlink tests (`compatibility.test.mjs`, `quality-gates-work-order.test.mjs` #174 traversal) fail on a Windows token without the symlink privilege; they pass in CI.
