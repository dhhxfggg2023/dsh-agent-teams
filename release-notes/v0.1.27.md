# v0.1.27 — installs on any Harness version, verified on 0.2.1-rc.3

Release on npm `latest`; recommended host: Harness `0.2.1-rc.3`. Host versions and plugin versions stay independent.

## Installation no longer depends on the host version

- Harness peers are declared as `*`. Before this release every `@deepseek-ai/dsh-*` peer enumerated exact released versions, so a host that shipped after the last plugin release was rejected at install time with an ERC/plugin-manager mismatch. A host bump no longer needs a plugin release to be installable.
- The versions this repository actually tests stay declared in [compatibility.json](../compatibility.json): `supportedHosts` is the tested matrix and `hostCorridor` is the range the project claims. `doctor` reports a host inside the corridor but outside the matrix as `corridor-untested` instead of `unsupported`, and still fails on a mixed cohort, a missing runtime peer, or duplicate identities.
- Runtime adapters were already capability-based (`startActivation` / `startContinuable` / host queue symbols); an unsupported host fails with a named diagnostic instead of guessing. Installation succeeding is therefore not a claim that an untested host behaves.

## Harness 0.2.1-rc.3

- Development and peer-verified cohort moved to `0.2.1-rc.3` (300 packages, complete closure). `0.2.1-rc.2` is retained as a legacy target.
- No agent, session, subagent, tools, system-prompt or plugin-manager contract used by AgentTeams changed between rc.2 and rc.3; typecheck, build and the harness-contract suite pass unchanged.

## Fixes

- `agent_teams_remove_member` no longer resets **failed** and **cancelled** tasks to `pending` and wipes their recorded verdict, findings, verification output and acceptance results. Only non-terminal tasks are requeued; terminal evidence survives member removal, matching `agent_teams_delete` and `agent_teams_resume`.
- A team can no longer be named `archive`: that id collides with the archive root, which made the team undeletable (rename into its own subtree) and made its cold-resumed members hydrate without the member tool restriction.
- `scripts/git-artifacts.mjs` hashes repository-normalized bytes (CRLF→LF) and uses stamp schema 2, so a Windows checkout and the Ubuntu CI checkout agree on the same source instead of recording the author's line endings. Added `.gitattributes` (`* text=auto eol=lf`).
- `scripts/harness-runtime-verify.mjs` and the CI matrix gate read the recommended host from `compatibility.json` instead of a hard-coded version string, so the real plugin-manager installation evidence cannot silently disappear on the next host bump.
- `scripts/fallback-tdd.mjs` had a tautological assertion (`!x || y` where `y` was already asserted); it now tests the forbidden sentence.
- `scripts/verify-package.mjs` (client bundle id, patch name, publish access, optional peers) is wired into `pnpm verify`; it previously shipped but was never run.
- pnpm appends its own YAML keys to `pnpm-workspace.yaml` on every install, which made the compatibility gate throw on a JSON parse. The gate now reads the `overrides` object through a tolerant reader.

## Verification

- `pnpm build`, `pnpm typecheck`, `walked verify chain` on the rc.3 cohort; see [0.2.1-rc.3 evidence](../docs/harness-0.2.1-rc.3/README.md) for the exact commands and the environment limits (Windows symlink tests require Developer Mode and are skipped/failing on the machine that produced this release).
