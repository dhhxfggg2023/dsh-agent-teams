# v0.1.29 — the upstream team workspace joins this line

Release on npm `latest`; recommended host: Harness `0.2.1-rc.3`. This release merges upstream `main` (17 commits, through its 0.1.26 release) into this line, which keeps its own durability fixes and its version-agnostic host policy. No host-facing plugin API changed.

## Merged from upstream

- **Team workspace refresh.** Light workspace cards, responsive member and task columns, a completion summary and the captain's latest unread messages. Dark mode, keyboard access and the existing team controls are preserved. ([#266](https://github.com/NanmiCoder/dsh-agent-teams/pull/266))
- **Claimed tasks are displayed apart from open, blocked and running ones.** This corrects the visual projection; it does not claim to resolve every cause of a task remaining claimed. ([#264](https://github.com/NanmiCoder/dsh-agent-teams/pull/264))
- **Optional tool inputs are treated as omitted.** A gateway-materialized empty inline plan and empty optional member fields no longer change behaviour, and an empty optional task assignee is normalized before claiming. ([#242](https://github.com/NanmiCoder/dsh-agent-teams/pull/242))
- **Stored session formats are read from the live host**, including after a session-module replacement, and legacy AgentTeams messages stay compatible. ([#240](https://github.com/NanmiCoder/dsh-agent-teams/pull/240), [#236](https://github.com/NanmiCoder/dsh-agent-teams/pull/236))
- The upstream regression suites for those fixes now run in this line's gates: `scripts/issue-234.test.mjs`, `issue-236.test.mjs`, `issue-236-stale-module.test.mjs`, `issue-262.test.mjs` in `pnpm verify:issue-regressions`, and `scripts/workspace-summary.test.mjs` in `pnpm verify:harness-contract`.

## Kept from this line

- The version-agnostic peer policy: every `@deepseek-ai/dsh*` peer is `*`, the tested matrix lives in `compatibility.json` (recommended `0.2.1-rc.3`, corridor `>=0.2.1-rc.1 <0.3.0` and older lines), and `scripts/doctor.mjs` reports a host outside the matrix as untested rather than unsupported.
- The 0.1.28 durability fixes: `releaseHandoffFences` releases an interrupted hand-off, a mailbox whose team was archived keeps the message body it was carrying, settled mailbox records are compacted inside the acknowledgement write, and the staged-plan editor keeps unsaved edits.
- The captain tool `agent_teams_set_member_model` (15 business tools in total), which upstream does not have. Both READMEs previously said 14; they now say 15.

## Merge resolution

The only conflicts were version strings and generated files: `README.md`, `README_ZH.md`, `package.json` (version), `lib/client.js`, `lib/client.js.map`, `lib/git-artifact-stamp.json`, and `release-notes/v0.1.26.md` (add/add — both lines released their own 0.1.26). The READMEs keep this line's version and compatibility text with upstream's new sections merged in by git; `package.json` keeps this line's version, peers, devDependencies and `files[]`, and took upstream's test wiring, which merged cleanly; the fork's own 0.1.26 note is retained; `lib/` was regenerated with `pnpm build`.
